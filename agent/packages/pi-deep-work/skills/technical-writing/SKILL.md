# Technical writing

- Lead with the answer or user-visible outcome.
- Use concrete repository terms, symbols, commands, and measured results.
- Keep one idea per sentence and one name per concept.
- Remove generic framing, promotional language, fake enthusiasm, and repeated conclusions.
- Use headings only when they help scanning.
- Cite only artifacts that were actually read or produced.
- Preserve uncertainty and explicit limitations.
- Never turn a passing proxy into a stronger verification claim.
- Keep implementation detail after user and maintainer impact.
